# Documentation

## How to use

1. Add the GitHub repository to Home Assistant: <https://github.com/ernestoguimaraes/ha-addon-ngrok>
2. Install the **ngrok Client Installer (Unofficial)** add-on. It is available for `aarch64` and `amd64`.
3. Create an ngrok account and copy your auth key.
4. Configure the add-on options (see descriptions below). Enter a valid ngrok authentication token as `auth_token`; it is required to authenticate with ngrok.
5. Add this addon to your `trusted_proxies` list in `configuration.yaml`.

    ```yaml
      http:
        use_x_forwarded_for: true
        trusted_proxies:
        - 127.0.0.1
        - 172.30.32.0/24
        - 172.30.33.0/24
    ```

    **Note**: _If you've modified your Supervisor or Docker network you may_
    _need to update the addresses for your system. See [Home Assistant's documentation][trusted_proxies_docs]_
    _for more info._

6. Start the addon
7. Restart Home Assistant Core

The ngrok inspector is exposed on TCP port `4040` by default. Open the add-on's
Web UI to inspect active tunnels. If you did not specify a `subdomain` or
`hostname`, the public URL is generated by ngrok and is shown there; you can also
read it through the [client API](#home-assistant-integration).

Example add-on configuration:

```yaml
log_level: info
auth_token: my-auth-token
region: us
tunnels:
  - name: hass
    proto: http
    addr: 8123
    inspect: false
    auth: ""
```

## Options

**Note**: _Remember to restart the add-on when the configuration is changed._

The following values are the add-on defaults:

```yaml
log_level: info
auth_token: ""
region: us
tunnels:
  - name: hass
    proto: http
    addr: 8123
    inspect: false
    auth: ""
```

### Option: `log_level`

Controls the add-on log verbosity. Supported values are `crit`, `warn`, `error`,
`info`, and `debug`. The default is `info`.

### Option: `auth_token`

Your ngrok authentication token. Enter a valid token to authenticate with ngrok
and establish a tunnel.

### Option: `region`

Specifies where the ngrok client will connect to host its tunnels. The following
options are available:

| **Option** | **Location**  |
| :--------: | :------------ |
| us         | United States |
| eu         | Europe        |
| ap         | Asia/Pacific  |
| au         | Australia     |
| sa         | South America |
| jp         | Japan         |
| in         | India         |

### Option: `tunnels`

A list of tunnels. Each tunnel must specify `name`, `proto`, and `addr`.
Tunnel names must be unique. For a numeric port such as `8123`, the add-on
forwards to `172.30.32.1:8123`; `addr` can also be an IPv4 address and port in
`address:port` form. IPv6 addresses and hostnames are not accepted by the
add-on's configuration schema. For details about ngrok tunnel options, see
[ngrok's documentation][ngrok_docs_tunnels].

| Option         | Protocol  | Description |
| -------------- | --------- | ----------- |
| `name`*        | all       | Unique name for this tunnel. |
| `proto`*       | all       | Tunnel protocol: `http`, `tls`, or `tcp`. |
| `addr`*        | all       | Destination port (`1`-`65535`) or IPv4 address and port (`address:port`). A port is forwarded to `172.30.32.1`. |
| `inspect`      | http      | Enable HTTP request inspection. Defaults to `false`. |
| `auth`         | http      | HTTP Basic Authentication credentials. Defaults to an empty string. |
| `host_header`  | http      | Rewrite the HTTP `Host` header; omit to leave it unchanged. |
| `bind_tls`     | http      | Bind an HTTPS endpoint (`true`) or an HTTP endpoint (`false`). |
| `subdomain`    | http, tls | Subdomain name to request. |
| `hostname`     | http, tls | Hostname to request (requires a reserved ngrok domain and DNS configuration). |
| `crt`          | tls       | Path to a PEM TLS certificate for terminating TLS before forwarding locally. |
| `key`          | tls       | Path to the matching PEM TLS private key. |
| `client_cas`   | tls       | Path to a PEM certificate authority used to verify incoming TLS client certificates. |
| `remote_addr`  | tcp       | Remote TCP address in IPv4 `address:port` form. |
| `metadata`     | all       | User-defined metadata exposed through the ngrok service API. |

*required

The add-on schema allows `inspect`, `host_header`, `bind_tls`, `subdomain`,
`hostname`, `crt`, `key`, `client_cas`, `remote_addr`, and `metadata` to be
omitted. `auth` is present by default as an empty string.

## Home Assistant Integration

You can leverage the ngrok client API to expose your tunnel status to Home
Assistant. This is done by creating a REST API sensor in your Home Assistant
`configuration.yaml`.

### Example: Get Public URL

If you want to monitor the public URL that ngrok generates, you can do that through
a [RESTful sensor][rest_docs] in Home Assistant.

1. Add this to your `configuration.yaml` or create a new [package file][packages_docs].

    ``` YAML
    sensor:
      - platform: rest
        resource: http://localhost:4040/api/tunnels/hass
        name: Home Assistant URL
        value_template: '{{ value_json.public_url }}'
    ```

    **Note**: _If you changed the default tunnel name, replace `hass` in the_
              _example with your tunnel name._

2. Reboot Home Assistant Core

Now you will have a sensor called `sensor.home_assistant_url` You could then use
this to create an automation each to alert you of the public url.
